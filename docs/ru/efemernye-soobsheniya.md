# Эфемерные сообщения

Эфемерное сообщение рисуется поверх чата для одного участника. Остальные его не видят, и в историю чата оно не попадает — удалять потом нечего, потому что сообщения в чате и не было.

Появились в Bot API 10.3. До этого у бота, которому есть что сказать приватно, было три неудобных варианта: написать в группу и дать прочитать всем, написать пользователю в личку и надеяться, что он раньше запускал бота, или уместить ответ в callback-алерт, куда влезает пара строк.

{% hint style="info" %}
Задумывались они для общих чатов, но обычный случай — ответ на нажатие кнопки — работает и в личке с ботом. Чего личка дать не может, так это прав администратора, поэтому пути, которым они нужны, там закрыты. Что именно — в таблице ниже.
{% endhint %}

## Когда Telegram их принимает

Именно от этого зависит, заработает ваш код или нет, поэтому — до примеров. Telegram разрешает эфемерное сообщение ровно в трёх случаях:

| | Нужны права админа? | Окно | Работает в личке? |
| --- | --- | --- | --- |
| Ответ на callback query с указанием его id | нет | 15 секунд | да |
| Ответ на входящее эфемерное сообщение | нет | 15 секунд | да |
| Отправка любому участнику чата, кроме ботов | **да** | в любой момент | нет — в личке админов не бывает |

Первые два — это способ *продолжить* начатое пользователем. Третий — единственный способ *начать*, и для него бот должен быть администратором чата.

Если условие не выполнено, Telegram отвечает:

```
Bad Request: BOT_NOT_ADMIN
```

Эта ошибка означает, что бот пошёл третьим путём без нужных прав — чаще всего потому, что эфемерное сообщение отправлено из обычного обработчика команды, а не из нажатия кнопки.

## Ответ на нажатие кнопки

Обычный случай, и никаких особых прав он не требует.

```csharp
using PRTelegramBot.Attributes;
using PRTelegramBot.Interfaces;
using PRTelegramBot.Services.Messages;

[InlineCallbackHandler<MyHeader>(MyHeader.ShowBalance)]
public static async Task ShowBalance(IBotContext context)
{
    await MessageSender.SendEphemeral(context, "Ваш баланс — 42 ⭐.");
}
```

`SendEphemeral` берёт нужное из текущего update: пользователя, который увидит сообщение, и callback query, на который отвечает, — чтобы Telegram понимал, к какому нажатию это относится и что мы укладываемся в 15 секунд.

## Продолжение внутри оверлея

Ответ на эфемерное сообщение сам обязан быть эфемерным, и на него тоже даётся 15 секунд. Цель ответа фреймворк подставляет из update, поэтому продолжение не требует лишнего кода:

```csharp
[ReplyMenuHandler("Да")]
public static async Task Confirm(IBotContext context)
{
    // Если это пришло изнутри эфемерного оверлея, ответ останется в нём.
    await MessageSender.SendEphemeral(context, "Готово.");
}
```

Входящее эфемерное сообщение несёт `Message.EphemeralMessageId` — именно его фреймворк копирует в [`OptionMessage.ReplyToEphemeralMessageId`](api/klassy/optionmessage.md). Если задать это свойство самому, приоритет будет у вашего значения.

## Начать разговор — только админу

Отправка из обычного обработчика команды или обращение к тому, кто не вызывал update, означает, что цитировать нечего. Это третий путь, и для него бот должен быть администратором группы:

```csharp
[ReplyMenuHandler("Уведомить")]
public static async Task Notify(IBotContext context)
{
    // Требует, чтобы бот был администратором этого чата.
    await MessageSender.SendEphemeral(context, moderatorId, "Пара слов, только для вас.");
}
```

## Заменить сообщение, а не накрыть его

По умолчанию оверлей появляется поверх исходного сообщения, и оно остаётся на месте. Флаг `replaceCallbackQueryMessage` ставит эфемерное сообщение вместо него — только для этого пользователя. Остальные в чате по-прежнему видят исходное нетронутым.

```csharp
await MessageSender.SendEphemeral(context, "Меню исчезло — для вас.", replaceCallbackQueryMessage: true);
```

{% hint style="danger" %}
**Замена работает только в группе.** В личке Telegram отвечает `MESSAGE_ID_INVALID` — заменять не на чем, общей ленты там нет, а сообщение один на один правится методами редактирования. Обычный эфемерный ответ выше работает и там, и там, так что это ограничение самого флага, а не эфемерных сообщений.

В документации Bot API это не написано. Так отвечает сам API — проверено с обеих сторон: в личке отказ, в группе работает.
{% endhint %}

{% hint style="warning" %}
Флаг работает только для нажатия кнопки. Если update не callback query, фреймворк его не выставляет, потому что Telegram такую комбинацию отклоняет.

Он также должен оставаться выключенным для нажатия, пришедшего из эфемерного сообщения: такие правятся методами редактирования эфемерных сообщений, а не заменой.
{% endhint %}

## Через OptionMessage

`SendEphemeral` — это удобная обёртка над одним свойством. Любой метод, принимающий [`OptionMessage`](api/klassy/optionmessage.md), можно сделать эфемерным, задав его напрямую — так отправляются фото, файлы и [rich-сообщения](rich-soobsheniya.md):

```csharp
var option = new OptionMessage
{
    EphemeralMessageParameters = new EphemeralMessageParameters { ReceiverUserId = userId }
};

await MediaSender.SendPhotoWithUrl(context, chatId, "Ваш чек", receiptUrl, option);
```

Обычный id пользователя приводится к этим параметрам неявно, поэтому `EphemeralMessageParameters = userId` достаточно, когда больше задавать нечего. Учтите: этот путь не проставляет id callback query, так что требование к правам администратора остаётся в силе, пока вы не заполните его сами.

Свойство пробрасывают [`MessageSender`](api/klassy/messagesender.md) и [`MediaSender`](api/klassy/mediasender.md) — для фото, файлов и медиа по URL. Медиагруппы его не принимают: это ограничение Bot API, а не пробел во фреймворке.

{% hint style="info" %}
Доставка не гарантируется. Telegram не станет держать эфемерное сообщение для пользователя, который сейчас офлайн, поэтому не отправляйте так то, что пользователь не должен пропустить. Для этого — обычное сообщение.
{% endhint %}
